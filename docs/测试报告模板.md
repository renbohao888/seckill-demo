# 秒杀压测报告

> 实测结果：200 并发 @ 库存 10，使用轻量并发脚本 `tools/concurrency_test.py`。

## 场景
- 接口：`POST /api/seckill?productId=1&userId={userId}`
- 并发数：**200**（不同用户并发）；Ramp-Up：0；循环：1。

## 结果

| 指标 | 值 |
|---|---|
| 发送请求总数 | 200 |
| 成功（code=200） | **10** |
| 失败·已抢光 | 190 |
| 失败·请求频繁 | 0 |
| 失败·手慢了 | 0（无丢单） |
| 总耗时(s) | 0.462 |
| QPS(约) | 432.8 |

## 一致性校验

| 校验 | 期望 | 实测 |
|---|---|---|
| DB 订单数 ≤ 库存(10) | 是 | 10（=库存） |
| 商品剩余库存 ≥ 0 | 是 | 0 |
| Redis `seckill:stock:1` ≥ 0 | 是 | 0 |
| 是否存在负数库存 | 否 | 无 |

## 结论

- 并发 200 下**成功单量 = 库存 10、卖光无超卖**，库存无负数，Redis/DB 一致。
- 说明「Redis 预减拦截 + 数据库 `stock>0` 条件更新兜底」在高并发下能**不超卖、不丢单**。
