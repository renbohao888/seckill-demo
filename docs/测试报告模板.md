# 秒杀压测报告模板

> 用 JMeter 实测后把【】数字替换为真实结果，再放进简历/汇报。

## 场景
- 接口：`POST /api/seckill?productId=1&userId=${userId}`
- 线程数：**200**；Ramp-Up：**0 秒**；循环：**1**；用户名从 CSV 参数化。

## 结果

| 指标 | 值 |
|---|---|
| 发送请求总数 | 【200】 |
| 成功（code=200） | 【10】 |
| 失败·已抢光 | 【】 |
| 失败·请求频繁 | 【】 |
| 失败·手慢了/版本冲突 | 【】 |

## 一致性校验

| 校验 | 期望 | 实测 |
|---|---|---|
| DB 订单数 ≤ 库存(10) | 是 | 【】 |
| 商品剩余库存 ≥ 0 | 是 | 【】 |
| Redis `seckill:stock:1` ≥ 0 | 是 | 【】 |
| 是否存在负数库存 | 否 | 【】 |

## 结论

- 并发 200 下**成功单量 = 库存 10，未出现超卖**，库存无负数，Redis/DB 一致。
- 说明「Redis 预减拦截 + 数据库乐观锁兜底」能在高并发下保证**不超卖**。
