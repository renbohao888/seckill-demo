# 秒杀接口测试用例

被测接口：`POST /api/seckill?productId={id}&userId={uid}`
返回结构：`{code, msg, data}`；`code=200` 成功，`code=400` 业务失败。

## 1. 等价类划分

| 类别 | 有效等价类 | 无效等价类 |
|---|---|---|
| 参数完整性 | productId、userId 均存在 | productId / userId 为空或缺失 |
| 库存 | 库存充足（如 10） | 库存为 0 |
| 用户状态 | 正常用户 | 同一用户 1 秒内重复请求（触发限流） |
| 商品状态 | 商品存在 | 商品不存在 |

## 2. 边界值分析

| 场景 | 预期 |
|---|---|
| 库存正好为 1，1 人抢购 | 成功 1 单，剩余 0 |
| 库存为 1，2 人并发 | 成功 1 单，另 1 人返回"已抢光 / 手慢了" |
| 库存为 0 | 直接返回"已抢光"，不落库 |
| 同一用户 1 秒内第 2 次请求 | 返回"请求过于频繁" |

## 3. 并发一致性用例（核心）

| 用例 | 操作 | 断言 |
|---|---|---|
| 并发不超卖 | 库存 10，200 个不同用户并发抢 | DB 订单数 ≤ 10；商品 stock ≥ 0；Redis `seckill:stock:1` ≥ 0 |
| 一用户一单 | 同一用户并发多次 | 用户仅有 1 条订单（幂等/限流生效） |
| Redis 与 DB 一致 | 压测结束后 | `seckill:stock:1` 与 DB `stock` 数值一致（无负数残留） |

## 4. 结果校验 SQL

```sql
-- 成功下单数（期望 ≤ 库存 10）
SELECT COUNT(*) FROM seckill_order WHERE product_id = 1;

-- 剩余库存（期望 ≥ 0）
SELECT stock, version FROM product WHERE id = 1;

-- 是否有负数库存（期望 0 行）
SELECT id FROM product WHERE stock < 0;
```
